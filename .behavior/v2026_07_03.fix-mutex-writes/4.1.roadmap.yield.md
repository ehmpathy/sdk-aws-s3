## how to read this roadmap

- phases run top-to-bottom; each phase depends on the ones above it (directional-deps: bottom of the
  stack first, so no unit imports a thing that does not yet exist).
- every phase declares **build**, **acceptance criteria** (the behavior it must satisfy), and
  **verify** (the exact command that proves it).
- `[ ]` = to do, `[x]` = done. mark a box only after its **verify** step is green.
- the grain of each unit sets its test type (per `rule.require.test-coverage-by-grain`):
  transformers → unit, communicators → integration (real s3), orchestrators → integration,
  contract barrel → acceptance + snapshots.

## phase 2 — transformers (pure → unit tests)

`rule.prefer.data-driven` (caselist unit tests); `rule.forbid.unit.remote-boundaries`.

- [ ] `[+] src/domain.operations/asS3Ref.ts` (+ `asS3Ref.test.ts`) — input → `S3Ref`; throws

- [ ] `[+] src/domain.operations/asS3ConditionHeaders.ts` (+ `.test.ts`) — `condition` → precondition
  headers. explicit return type `{ IfNoneMatch?: string; IfMatch?: string }`; omitted condition → `{}`

- [ ] `[+] src/domain.operations/throwMappedS3ConditionError.ts` (+ `.test.ts` + snapshot) — s3 error →

  raw. the mapper test carries the `.known-gap` comment for the 409 unit-coverage rationale and is the

**acceptance**: matches the blueprint condition→header + error→type tables exactly; 404 disambiguation

## phase 4 — orchestrators (compose → integration tests)

**read**: blueprint `codepath tree` + `contracts`; `rule.require.orchestrators-as-narrative`;
`rule.forbid.decode-friction-in-orchestrators`; `rule.forbid.as-cast` (overload discriminant lives in
`input`, not a second `options` arg).

- [ ] `[~] src/domain.operations/set.ts` (+ `.integration.test.ts`) — `function` overloads: default →

- [ ] `[~] src/domain.operations/getOne.ts` (+ `.integration.test.ts`) — overloads: default → body
  string; `include: { meta: true }` → `{ body, meta }`; null-on-absent even when meta requested.
- [ ] `[~] src/domain.operations/getAll.ts` (+ `.integration.test.ts`) — result field `content` → `body`
  (the one deliberate BREAKING change). integration + acceptance assert `.content` is `undefined` and

- [ ] `[~] src/domain.operations/del.ts` (+ `.integration.test.ts`) — `condition?: { etag: string }`
  passthrough (non-nullable — no delete-if-absent; no `include: { meta }` overload — no post-delete
  etag exists).
- [ ] `[+] src/domain.operations/condition.integration.test.ts` — cross-op matrix A/B/C: put-if-absent,
  compare-and-set, fenced release (compare-and-delete, one contiguous `[case3]` block), del-absent
  probe (case5), CAS-on-absent → 412 (case6).
- [ ] `[+] src/domain.operations/condition.concurrency.integration.test.ts` — live 409/412 concurrency

**acceptance**: overloads narrow the return type with no `as` cast; backwards-compat holds when

## dependency graph (why this order)

```
phase 0 (deps/barrel)
   └─> phase 1 (domain.objects)        # errors + S3Ref + context, imported by everything below
          └─> phase 2 (transformers)   # pure; consume domain.objects only
                 └─> phase 3 (communicators)   # consume transformers + domain.objects; real i/o
                        └─> phase 4 (orchestrators)   # compose communicators + transformers
                               └─> phase 5 (contract)   # barrel over orchestrators; acceptance
                                      └─> phase 6 (full-suite gate + release)
```

each phase's **verify** is the behavioral acceptance checkpoint; do not advance until it is green.
