## empirical findings (resolved vision [research] items)

- **del + condition.etag on an ABSENT object** → s3 returns **404 `NoSuchKey`**, NOT 412.
  the vision flagged this as unverified; now pinned by integration test. contract decision:
  map `NoSuchKey`/404 on a conditional op → `S3PreconditionFailedError`, so consumers catch
  one typed error for "my fenced write did not happen" (the expected object/etag is absent).
- **etag round-trip fidelity** → verified: the etag from `set`+meta equals the etag from
  `get.one`+meta, passed verbatim (quotes preserved) back into `condition.etag`.

## build-time decisions to flag for review

1. **`helpful-errors` promoted to a runtime dependency** (was devDep). the sdk's runtime deps
   grow from 1 (`@aws-sdk/client-s3`) to 2. the wisher approved "adds an error-lib dependency"
   in vision q3; `ConstraintError` was not in the installed 1.5.3, so upgraded to 1.7.3.
2. **409 `S3ConditionalConflictError` is internal-only (not publicly exported)** — the vision
   deferred the 409 *shape* to an architect stone. to avoid a premature public-api commitment, the
   class stays an internal domain.object: the mapper still converts a 409 to it (so a 409 is not
   propagated raw, honoring the vision), but it is NOT exported from `src/contract` / `src/index`.
   the public export waits for the architect stone to ratify the shape. it extends
   `MalfunctionError` (exit 1) as a retry signal. note: 409 is hard to trigger deterministically,
   so it is reachable via the mapper but not exercised by a live concurrent-collision test.
   (adjusted during self-review r1 has-pruned-yagni.)
3. **`function` overloads used for `set` / `getOne`** — the vision's "type overload" for
   input-dependent returns. this is the standard TS idiom; an arrow-only equivalent would need a
   forbidden `as` cast, so overloads are the justified mechanism.
4. **`S3PreconditionFailedError` inherits ConstraintError's http 400** (not 412) — an override of
   the static `code` conflicts with the base literal type; the real 412 status is conveyed by the
   class name + message, and exit 2 (caller-must-fix) is preserved.
