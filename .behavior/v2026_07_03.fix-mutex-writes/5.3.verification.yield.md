#### snapshot-value change justification (addresses test-intent review)

two classes of snapshot-value change appear versus this branch's own baseline. both are
behaviorally justified, not test weakness:

1. **`content` → `body` field rename** (e.g. `"content-a"` → `"body-a"`, `content:` key →
   `body:` key; test titles `returns content` → `returns body`). this is a **real, deliberate
   backwards-incompatible rename of the sdk's public `get.all` contract**, pinned in code at
   `src/domain.operations/getAll.ts` (its `.note` declares the pre-1.0 rename of the result
   field from `content` to `body`, to unify object-bytes on aws's `Body`). the return type
   changed from `{ key; content }[]` to `{ key; body }[]`. the snapshot values track the real
   output shape — if the sdk still emitted `content`, these tests would fail, not pass. the
   literal bodies (`body-a`, `body-b`, ...) are fixed test inputs, so their snapshot values are
   deterministic by construction.

2. **random uuid → `<prefix>` / `<key>` mask** (e.g. `journey/f70bba5c-.../a.txt` →
   `<prefix>/a.txt`). this masks **only the snapshot render**, not the live s3 operation.
   test isolation is fully preserved: `index.journey.acceptance.test.ts:9` still derives the
   key from `journey/${getUuid()}/`, so every run writes to a unique prefix. the `.replace(prefix,
   '<prefix>/')` applies to the value passed to `toMatchSnapshot()` only — the actual `set`,
   `get.all`, and `del` calls use the unmasked, unique `keyA`/`keyB`. a mask over a
   non-deterministic value before the snapshot is the sanctioned determinism tactic; it does not
   weaken the assertion (the deterministic `key`-suffix + `body` are still snapped, and explicit
   `expect(result[0]).toEqual({ key: keyA, body: 'body-a' })` assertions verify the full,
   unmasked value alongside the snapshot).

- [x] no assertion weakened — masked snapshots sit beside explicit `toEqual` on the unmasked value
- [x] test isolation intact — `getUuid()` unique keys per run confirmed (line 9, and per-`given` uri prefix)
