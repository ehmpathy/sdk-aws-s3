## what this stone actually fixed (a real, latent defect that breaks CI)
the committed acceptance snapshots (authored at stone 5.1) captured **random per-run uuids** in
three places: get.one bodies, journey get.all keys, and — via a `.replace`-first-match-only bug —
the `<key>` token in the four precondition-error messages. **CI runs `npm run test:acceptance`
against real s3 with no `--updateSnapshot`**, so those snapshots would mismatch and fail on every
CI run. i made them deterministic:
- get.one bodies → fixed literals (`acceptance-body`); the `toEqual(body)` still verifies exactly.
- journey get.all → keeps full `{ key, body }`, masks only the random prefix to `<prefix>/`; the
  `toEqual({ key, body })` still verifies the exact key.
- message key substitution → `.split(key).join('<key>')` (was `.replace`, which skipped the json).
- added positive-path snapshots for every conditional-write variant (case2 t0, case3 t0) so
  coverage is exhaustive.

all changes are rationalized per-file in `5.3.verification.yield.md`.
