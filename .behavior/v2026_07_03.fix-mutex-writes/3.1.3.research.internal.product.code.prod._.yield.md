# 3.1.3 internal research — prod codepath patterns

> researched against: wish `0.wish.md`, vision `1.vision.yield.md`, criteria `2.1` / `2.2`.
> scope: production codepaths only (test codepaths excluded). every claim cites the source file+line.

the repo already carries an ergonomic s3 wrapper (`sdkAwsS3 = { get: { one, all }, set, del }`).
the conditional-write wish extends that surface. below, each relevant prod pattern is enumerated
with a [REUSE] / [EXTEND] / [REPLACE] tag.

---

## pattern 1 — contract aggregation object [REUSE]

a single `sdkAwsS3` object aggregates the operations; typed errors + `S3Ref` are re-exported from
the contract barrel.

**[cite 1]** `src/contract/index.ts:15-22`
> ```ts
> export const sdkAwsS3 = {
>   get: {
>     one: getOne,
>     all: getAll,
>   },
>   set,
>   del,
> };
> ```

**[cite 2]** `src/contract/index.ts:11-13` — typed errors + ref surfaced publicly
> ```ts
> export { S3ConditionalConflictError } from '../domain.objects/S3ConditionalConflictError';
> export { S3PreconditionFailedError } from '../domain.objects/S3PreconditionFailedError';
> export type { S3Ref } from '../domain.objects/S3Ref';
> ```

relation to wish: the aggregation shape is untouched; the wish only enriches the member ops.
**[REUSE]** — the `sdkAwsS3` object and its `get/set/del` layout stay as-is. (note: `S3ConditionalConflictError`
is exported here now; the vision defers whether 409 stays public to an architect stone.)

## pattern 2 — `(input, context?)` with input-parse + optional injected client [REUSE / EXTEND]

every op takes `(input, context?)`, parses the ref via `asS3Ref`, and gets-or-creates the client
from an optional injected context.

**[cite 3]** `src/domain.operations/setS3Object.ts:26` — client get-or-create
> ```ts
> const client = context?.aws?.s3?.client ?? new S3Client({});
> ```

**[cite 4]** `src/domain.operations/set.ts:38-39` — input parse to ref
> ```ts
> // parse input to bucket + key
> const ref = asS3Ref(input);
> ```

relation to wish: the `(input, context?)` contract is reused verbatim; the wish **[EXTEND]s** the
`input` shape with `condition?` and `include?` fields. the context/client-injection pattern is
pure **[REUSE]**.

## pattern 3 — s3ref type by grain [REUSE]

`S3Ref<'object'>` models `{ uri } | { bucket, key }`; the conditional ops all operate on the
object grain.

**[cite 5]** `src/domain.objects/S3Ref.ts:47-49`
> ```ts
> export type S3Ref<TGrain extends keyof S3RefGrainMap = keyof S3RefGrainMap> =
>   | S3RefByUri
>   | S3RefGrainMap[TGrain];
> ```

relation to wish: `set` / `del` / `get.one` all key off `S3Ref<'object'>`, exactly as before.
**[REUSE]** — no ref-type change; conditional fields ride alongside the ref in `input`.

## pattern 4 — 404-as-null on read [REUSE]

`getOne` returns `null` when the object is absent (404), rather than a throw.

**[cite 6]** `src/domain.operations/getOne.ts:31-32`
> ```ts
> // fetch object (null when absent / 404)
> const object = await getS3Object({ ref }, context);
> if (object === null) return null;
> ```

relation to wish: the read's null-on-absent contract is preserved; the wish **[EXTEND]s** the
return with an opt-in meta envelope but keeps the null path (even the meta overload returns null
when absent — `getOne.ts:38`). **[REUSE]** of the null-on-404 pattern.

---

## pattern 5 — grain separation: orchestrator / communicator / transformer [EXTEND]

the wish introduced a clean 3-grain split so orchestrators read as narrative:

- **orchestrators** — `set` / `getOne` / `del` compose parse + i/o + meta-shape.
- **communicators** — `setS3Object` / `getS3Object` / `deleteS3Object` do the raw put/get/delete + error-map.
- **transformers** — `asS3ConditionHeaders` (condition → headers), `throwMappedS3ConditionError` (error → typed).

**[cite 7]** `src/domain.operations/setS3Object.ts:1-5` — communicator role stated
> ```
> .what = communicator that sends a (conditional) put to s3 and maps condition errors
> .why = isolates the raw i/o + error-map so the set orchestrator reads as narrative,
>        instead of an inline try/catch that a reader must simulate
> ```

**[cite 8]** `src/domain.operations/set.ts:41-45` — orchestrator composes the communicator
> ```ts
> // upsert object (conditionally, if a condition was supplied)
> const response = await setS3Object(
>   { ref, body: input.body, condition: input.condition ?? null },
>   context,
> );
> ```

relation to wish: the pre-wish `set`/`del` were flat (inline `PutObjectCommand`). the wish
**[EXTEND]s** them into orchestrator+communicator pairs — the communicators (`setS3Object`,
`getS3Object`, `deleteS3Object`) are net-new prod files that encapsulate the conditional i/o.

## pattern 6 — condition → precondition-header transformer [EXTEND — net new]

a single `condition.etag` field maps to s3's two mutually-exclusive write-condition headers.

**[cite 9]** `src/domain.operations/asS3ConditionHeaders.ts:14-18`
> ```ts
> // assert-absent → put-if-absent
> if (input.condition.etag === null) return { IfNoneMatch: '*' };
>
> // assert-etag → compare-and-set / compare-and-delete
> return { IfMatch: input.condition.etag };
> ```

relation to wish: this transformer did not exist pre-wish; it is the mechanism that realizes the
vision's `condition.etag` → `IfNoneMatch`/`IfMatch` map table. **[EXTEND]** (new leaf added to the
op family).

---

## pattern 7 — typed error map via `throwMappedS3ConditionError` [EXTEND — net new]

conditional errors (412 / 404 / 409) map to typed domain errors; all else rethrows raw.

**[cite 10]** `src/domain.operations/throwMappedS3ConditionError.ts:30-40`
> ```ts
> // 412 precondition failed → typed caller-must-fix error
> if (status === 412 || error.name === 'PreconditionFailed')
>   throw new S3PreconditionFailedError({ ref, condition, cause: error });
> // 404 no such key on a conditional op → the expected object/etag is absent...
> if (status === 404 || error.name === 'NoSuchKey')
>   throw new S3PreconditionFailedError({ ref, condition, cause: error });
> // 409 concurrent conflict → typed retry signal
> if (status === 409 || error.name === 'ConditionalRequestConflict')
>   throw new S3ConditionalConflictError({ ref, condition, cause: error });
> ```

relation to wish: pre-wish the repo used only plain `Error` (in `asS3Ref`) and passed through raw
`S3ServiceException`. the wish **[EXTEND]s** the error posture with typed domain errors — and the
404-branch encodes the resolved `[research]` result (external research topic 1: conditional del
of an absent object → 404). **[EXTEND]** of the error-map pattern.

---

## pattern 8 — typed error class over `helpful-errors` `ConstraintError` [EXTEND — net new]

`S3PreconditionFailedError extends ConstraintError` (caller-must-fix, exit 2), with an actionable
message and preserved `cause`.

**[cite 11]** `src/domain.objects/S3PreconditionFailedError.ts:15` + `22-27`
> ```ts
> export class S3PreconditionFailedError extends ConstraintError {
> ```
> ```ts
> input.condition.etag === null
>   ? 'to fix: the object is already present — delete it first, or omit condition to overwrite unconditionally.'
>   : 'to fix: re-read the object via get.one with include.meta to get its latest etag, then retry with condition.etag set to that value.',
> ```

relation to wish: pre-wish there was no error lib and no typed domain error. the wish **[EXTEND]s**
by inclusion of the `helpful-errors` dependency and a `ConstraintError` subclass, aligned with
ehmpathy fail-loud conventions. **[EXTEND]** (new error dependency + class).

---

## pattern 9 — type overload for input-dependent return [EXTEND — net new]

`set` / `getOne` return one of two shapes based on `include`, expressed via the `function` overload
idiom (an arrow-only form would need a forbidden `as` cast).

**[cite 12]** `src/domain.operations/set.ts:13-29`
> ```ts
> // default — returns void (backwards-compat)
> export function set(...): Promise<void>;
> // opt-in — returns the written object's etag
> export function set(...): Promise<{ meta: { etag: string } }>;
> ```

**[cite 13]** `src/domain.operations/getOne.ts:13-22` — same overload pattern on read
> ```ts
> // default — returns the body string (backwards-compat)
> export function getOne(input: S3Ref<'object'>, ...): Promise<string | null>;
> // opt-in — returns body alongside meta (etag)
> export function getOne(input: S3Ref<'object'> & { include: { meta: true } }, ...): Promise<{ body; meta } | null>;
> ```

relation to wish: pre-wish `getOne` was a single flat `string | null` and `set` was flat `void`.
the wish **[EXTEND]s** both with an opt-in-meta overload — the mechanism that preserves
backwards-compat (omit `include` → today's shape). **[EXTEND]**.

---

## pattern 10 — `getAll` output field rename `content → body` [REPLACE]

the vision's single deliberate break: unify the object-bytes term on `body`.

**[cite 14]** `src/domain.operations/getAll.ts` returns `{ key, body }[]` (the wish renamed the
extant `content` field to `body`, per `rule.require.ubiqlang`; see vision assumption 1 and the
build-decision in `5.1.execution.from_vision.yield.md`).

relation to wish: this is the one pattern the wish **[REPLACE]s** rather than extends — the
output field name `content` is replaced by `body`. every other op already used `body`; this
aligns `getAll` with the canonical term.
