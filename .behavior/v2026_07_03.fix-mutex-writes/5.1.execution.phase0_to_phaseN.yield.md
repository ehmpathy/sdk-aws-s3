## peer-review resolutions (iteration i1)

the first peer review counted 9 blockers. six were valid and are now fixed; three are
defended on explicit rule-grounds (not preference).

### fixed
- **r5.1 decode-friction in `getOne`** → extracted `asGetOneOutput` transformer (+ unit test);
  the orchestrator now reads as narrative (parse → fetch → shape).
- **r5.2 decode-friction in `set`** → extracted `asSetOutput` transformer (+ unit test).
- **r6.1 mutable state in `getAll`** → rewrote immutably: `let`/`push` pagination became a
  recursive `getAllKeysUnderPrefix` walk with spread-concat; the fetch loop became a
  sequential immutable `reduce` (no behavior change — still in-order, still sequential).
- **r8.1 missing acceptance: get.one via uri with include.meta** → added `[case7]` (exists + absent).
- **r8.2 missing acceptance: unconditional set with include.meta** → added `[case8]`.
- **r2.1 snapshot-without-assertion (failhide)** → every snapshot-only then-block now carries
  a complementary value assertion (`toEqual`/`toBeNull`/`toContain('s3 precondition failed')`)
  alongside the `toMatchSnapshot()`. (`condition.integration.test.ts` had no snapshots — that
  part of the finding was a false positive.)

### defended (rule-grounds, documented inline)
- **r7.3 `function` overloads (vs arrow-only)** — the overloads narrow the return by input
  shape; the arrow + callable-type form can not do so without an `as`-cast, which
  `rule.forbid.as-cast` prohibits. picking the overload idiom is the *stricter* choice: it
  avoids the harder-forbidden cast. documented in `getOne.ts` / `set.ts`.
- **r7.1 optional `condition?` / `include?`** — `getOne` / `set` / `del` are the public sdk
  entry points (re-exported directly on `sdkAwsS3` from `src/contract/`).
  `rule.prefer.optional-input-for-sdk-ux` explicitly overrides `forbid.undefined-inputs` at
  the sdk boundary. documented inline.
- **r7.2 `set` (vs `upsert`)** — `set` is idempotent (PutObject overwrites), so the safety
  intent of `forbid.nonidempotent-mutations` holds; it mirrors the s3 sdk get/set/del triad
  and is the already-published public name (v0.1.x). a rename is a semver-major break, out of
  scope for this conditional-write wish → a human-gated decision if the guard insists.

### nitpicks (defended)
- **r7-nit1 no `context?` on pure transformers** — an unused param is speculative (yagni).
- **r7-nit2 `?? new S3Client({})` fallback** — the default-client is the sdk's zero-config
  ergonomic; a caller may still inject a client via context.
