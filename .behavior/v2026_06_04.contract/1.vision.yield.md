# vision: sdk-aws-s3

## the outcome world

### day-in-the-life

a developer needs to cache expensive computation results in S3 for distributed access. today:

```ts
// before: raw AWS SDK
import { S3Client, GetObjectCommand, PutObjectCommand } from '@aws-sdk/client-s3';

const client = new S3Client({ region: 'us-east-1' });

// get an object: 15+ lines to handle correctly
let content: string | undefined;
try {
  const response = await client.send(new GetObjectCommand({
    Bucket: 'my-bucket',
    Key: 'cache/results.json'
  }));
  content = await response.Body?.transformToString();
} catch (error) {
  if (error.name === 'NoSuchKey' || error.$metadata?.httpStatusCode === 404) {
    content = undefined;
  } else {
    throw error;
  }
}

// set an object
await client.send(new PutObjectCommand({
  Bucket: 'my-bucket',
  Key: 'cache/results.json',
  Body: JSON.stringify(data),
}));
```

with sdk-aws-s3:

```ts
// after: sdk-aws-s3
import { sdkAwsS3 } from 'sdk-aws-s3';

// get: one line, returns null for 404
const content = await sdkAwsS3.get.one({ uri: 's3://my-bucket/cache/results.json' });

// set: one line
await sdkAwsS3.set({ uri: 's3://my-bucket/cache/results.json', body: JSON.stringify(data) });
```

### before/after contrast

| aspect | before | after |
|--------|--------|-------|
| get object | 15+ lines with try/catch | 1 line |
| 404 handle | manual error parse | automatic (returns `null`) |
| URI format | bucket + key always separate | URI or bucket+key |
| mental load | remember Command classes | remember `get`, `set`, `del` |
| client management | manual construction/cleanup | optional injection |

### "aha" moment

> "wait, i can just pass an s3 URI and it figures out bucket and key? and 404s just return null? that's how it should have worked all along."

## user experience

### usecases

1. **distributed cache storage** — write cache entries to S3 for access across instances
2. **artifact storage** — upload build outputs, read later for deployment
3. **data lake ingestion** — write processed data, list and read for analytics
4. **backup/restore** — dump state to S3, restore when needed

### contract overview

| operation | input | output | semantics |
|-----------|-------|--------|-----------|
| `get.one` | `{ uri }` or `{ bucket, key }` | `string \| null` | returns `null` for 404 |
| `get.all` | `{ uri }` or `{ bucket, prefix }` | `Array<{ key, content }>` | lists + fetches all matched |
| `set` | `{ uri, body }` or `{ bucket, key, body }` | `void` | upserts object |
| `del` | `{ uri }` or `{ bucket, key }` | `void` | deletes if exists |

### typical journey

```ts
import { sdkAwsS3 } from 'sdk-aws-s3';

// 1. check if cached
const cached = await sdkAwsS3.get.one({ uri: 's3://my-bucket/cache/results.json' });
if (cached) return JSON.parse(cached);

// 2. compute expensive result
const result = await computeExpensiveOperation();

// 3. cache for next time
await sdkAwsS3.set({ uri: 's3://my-bucket/cache/results.json', body: JSON.stringify(result) });

return result;
```

### timeline

1. **install**: `npm install sdk-aws-s3`
2. **import**: `import { sdkAwsS3 } from 'sdk-aws-s3';`
3. **use**: call operations with URI or bucket+key
4. **optionally inject context**: pass custom S3Client for test or custom config

## mental model

### how users would describe it

> "it's like a simpler interface to S3 — you give it a URI and it does the right action. 404s return null instead of throw."

### analogies

- **filesystem** — `get.one` is like `readFile` that returns null if absent, `set` is like `writeFile`, `del` is like `unlink`
- **key-value store** — `get.one(key)` returns value or null, `set(key, value)` saves
- **object with methods** — `sdkAwsS3.get.one()`, `sdkAwsS3.set()` — verbs match operations

### terminology

| user says | we say | means |
|-----------|--------|-------|
| "get a file from S3" | `get.one` | retrieve single object |
| "list objects" | `get.all` | list + fetch with prefix |
| "upload/write" | `set` | put object (upsert) |
| "delete/remove" | `del` | delete object |
| "s3 path" | `uri` | s3://bucket/key format |

## evaluation

### how well does it solve the goals?

| goal | score | notes |
|------|-------|-------|
| reduce boilerplate | excellent | 15+ lines → 1 line for get |
| handle 404s graceful | excellent | automatic null, not throw |
| ergonomic API | excellent | URI format + verbs |
| testability | good | context injection for client |
| type safety | good | full TypeScript types |

### pros

- **dramatic less code** — each operation is a single line
- **pit of success** — 404 handle built-in, no forgotten try/catch
- **familiar URI format** — developers already think in s3:// URIs
- **flexible input** — both URI and bucket+key supported
- **testable** — inject mock client via context

### cons

- **abstraction cost** — one more layer between user and AWS SDK
- **limited operations** — only get/set/del/list, no multipart upload, version-aware, etc.
- **string content only** — body is string, not stream (intentional for simplicity)

### edgecases & pit of success

| edgecase | behavior | pit of success |
|----------|----------|----------------|
| object not found | `get.one` returns `null` | no try/catch needed |
| bucket not found | throws (bucket should exist) | fail loud, not silent |
| empty prefix list | `get.all` returns `[]` | no special handle |
| delete non-existent | silent success | idempotent delete |
| malformed URI | throws with clear message | fail fast with context |

## open questions & assumptions

### assumptions made

1. **string content is sufficient** — users don't need stream for this use case
2. **404 = null is desired** — not all APIs want silent 404s
3. **no multipart upload** — large files outside scope
4. **no version-aware operations** — version operations outside scope
5. **credential resolution via AWS SDK defaults** — env vars, IAM role, etc.

1. **[answered]** `get.all` fetches content — wisher specified `Array<{ key, content }>`

## groundwork

### external research

**verified**: @aws-sdk/client-s3 v3.1042.0 API (from node_modules)

- **GetObjectCommand**: returns `Body` stream, must call `transformToString()` to get content
- **NoSuchKey error**: has `name: "NoSuchKey"` property, extends `__BaseException`
- **error.$metadata**: contains `httpStatusCode` for HTTP-level 404 detection
- **S3Client**: constructed with region, optional credentials, optional endpoint
- **dual 404 check**: confirmed necessary — some 404s come as `NoSuchKey`, others as httpStatusCode 404 without the error name

**key code pattern** (from SDK research):
```ts
try {
  const response = await client.send(new GetObjectCommand({ Bucket, Key }));
  return await response.Body?.transformToString() ?? null;
} catch (error) {
  if (error.name === 'NoSuchKey' || error.$metadata?.httpStatusCode === 404) {
    return null;
  }
  throw error;
}
```

### internal research

**verified**: this repo

- `src/index.ts:1-7` — empty placeholder, no extant behavior
- `package.json` — @aws-sdk/client-s3@3.1042.0 already installed
- follows ehmpathy SDK patterns (per wish)

**patterns to follow**:
- `sdkAwsS3` as exported object (not class)
- `get.one`, `get.all`, `set`, `del` method name pattern
- `(input, context?)` pattern per briefs
- optional context for client injection

## what is awkward?

### `get.all` fetch content

the wish shows `get.all` returns `Array<{ key, content }>`, which means it fetches every object that matches the prefix. this is:
- **slow** — N network calls for N objects
- **expensive** — data transfer costs
- **risky** — prefix with 1000 objects = 1000 fetches

alternative: `list` returns keys, user selectively calls `get.one`. but this is more code.

**recommendation**: keep `get.all` as specified, but document the performance characteristics. users who need just keys can call AWS SDK directly.

### URI vs bucket+key duplication

every operation accepts both formats:
```ts
sdkAwsS3.get.one({ uri: 's3://bucket/key' });
sdkAwsS3.get.one({ bucket: 'bucket', key: 'key' });
```

this is **good** for flexibility but creates:
- two input shapes to validate
- documentation overhead
- slight type complexity

**recommendation**: accept the tradeoff — flexibility wins. use discriminated union for types.

### `body` as string only

wish specifies `body: string`. this means:
- no Buffer support
- no stream support
- users must stringify objects themselves

**recommendation**: keep simple. string covers 95% of use cases (JSON, text). users who need binary/streams can use AWS SDK directly. this is a convenience wrapper, not a full replacement.

### `void` return for `set` and `del`

AWS SDK returns ETag, VersionId, etc. from put/delete. we discard this.

**recommendation**: acceptable for simplicity. users who need version info can use AWS SDK directly. add later if requested.
