# playtest: sdk-aws-s3

## prerequisites

- [ ] AWS credentials configured (via `~/.aws/credentials` or env vars)
- [ ] test bucket accessible

```sh
# step 1: unlock credentials
rhx keyrack unlock --owner ehmpath --env test

# step 2: verify bucket is accessible
rhx git.repo.test --what acceptance --mode apply
```

---

## sandbox

all playtest operations target the test bucket specified in `src/__test_assets__/getTestBucket.ts`. no local filesystem pollution.

---

## run tests

### acceptance tests

```sh
rhx git.repo.test --what acceptance --mode apply
```

covers:
1. **set + get.one roundtrip** — write then read returns content
2. **get.one absent returns undefined** — 404 handled gracefully
3. **set overwrites extant object** — upsert semantics
4. **del removes object** — object absent after delete
5. **get.all lists objects with prefix** — returns array with keys and contents
6. **del absent is idempotent** — no error on delete of non-existent key
7. **invalid URI scheme throws** — `http://` rejected
8. **malformed URI throws** — `s3://bucket` (no key) rejected

### integration tests

```sh
rhx git.repo.test --what integration --mode apply
```

covers:
- URI format works for all operations (`s3://bucket/key`)
- context injection for S3 client reuse

---

## pass/fail criteria

**pass if**:
- [ ] acceptance tests pass
- [ ] integration tests pass
- [ ] undefined returned for absent keys (not null, not error)
- [ ] URI format works for all operations

**fail if**:
- [ ] any test fails
- [ ] get.one returns a value other than `undefined` for absent key
- [ ] URI parse fails for valid URIs

---

## test locations

- `src/contract/index.acceptance.test.ts` — contract-level acceptance tests
- `src/domain.operations/*.integration.test.ts` — operation-level integration tests
- `src/__test_assets__/getTestBucket.ts` — single source of truth for test bucket
