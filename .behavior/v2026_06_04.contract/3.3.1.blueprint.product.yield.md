# blueprint: sdk-aws-s3

## summary

build an ergonomic S3 SDK wrapper with:
- `sdkAwsS3.get.one` — fetch single object, return `string | null`
- `sdkAwsS3.get.all` — fetch all objects with prefix, return `Array<{ key, content }>`
- `sdkAwsS3.set` — upsert object
- `sdkAwsS3.del` — delete object

all operations accept URI (`s3://bucket/key`) or bucket+key input.

## codepath tree

```
src/contract/index.ts
└── [+] sdkAwsS3                              # exported SDK object
    ├── [+] get.one                           # → getOne orchestrator
    ├── [+] get.all                           # → getAll orchestrator
    ├── [+] set                               # → set orchestrator
    └── [+] del                               # → del orchestrator

src/domain.operations/asS3Ref.ts
└── [+] asS3Ref                               # transformer: URI → inline type
    ├── input: { uri } | { bucket, key }
    └── output: { bucket: string; key: string }

src/domain.operations/getOne.ts
└── [+] getOne                                # orchestrator
    ├── call asS3Ref (transformer)
    ├── call S3Client.send(GetObjectCommand)  # communicator (inline)
    ├── handle 404 → return null
    └── return string content

src/domain.operations/getAll.ts
└── [+] getAll                                # orchestrator
    ├── call asS3Ref (transformer)
    ├── loop: S3Client.send(ListObjectsV2Command)  # communicator
    │   └── handle pagination via ContinuationToken
    ├── for each key: call getOne
    └── return Array<{ key, content }>

src/domain.operations/set.ts
└── [+] set                                   # orchestrator
    ├── call asS3Ref (transformer)
    └── call S3Client.send(PutObjectCommand)  # communicator (inline)

src/domain.operations/del.ts
└── [+] del                                   # orchestrator
    ├── call asS3Ref (transformer)
    └── call S3Client.send(DeleteObjectCommand)  # communicator (inline)

src/contract/types.ts
└── [+] ContextSdkAwsS3                       # context type
    └── aws?: { s3?: { client?: S3Client } }
```

### snapshots

acceptance tests will snapshot all contract outputs:

**positive cases**:
- `getOne` return value (string)
- `getOne` return value (null for absent)
- `getAll` return value (array shape)
- `set` return value (void/undefined)
- `del` return value (void/undefined)

**negative cases**:
- invalid URI scheme error
- malformed URI error
- bucket not found error

**journey checkpoints**:
- [t0] object absent (null)
- [t2] object created (content)
- [t4] object updated (content)
- [t5.5] invalid URI error (error message)
- [t7] object deleted (null)

## design notes

### inline communicators

S3 client calls are inline in orchestrators (not separate communicator files) because:
- each operation uses a single command
- no shared logic across operations
- follows simplicity principle (no premature abstraction)

### pagination in getAll

`getAll` handles ListObjectsV2 pagination internally:
- loop while `ContinuationToken` is present
- collect all keys before fetch
- then fetch content for each key

### context injection

optional `context.aws.s3.client` allows:
- test injection (mock S3Client)
- custom configuration (region, endpoint)
- default: create S3Client on demand
